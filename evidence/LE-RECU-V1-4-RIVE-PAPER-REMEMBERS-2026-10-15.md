## Direction decision (reversible)

Both directions share one generator, one state machine and one view model, so they are directly comparable.

- **A — Fiber & Ink** (`fiber`): ivory fibres, a bristle fan that leans toward the finger, an ink line that is drawn then absorbs into the paper (feathered bloom, dry-brush streak), a double-ring red seal with a pressure wave and a paper dent, a dashed ring for "pending", a slit for "failed". Second impression = ink-black double ring.
- **B — Press** (`press`): topographic pressure contours, a block-bar redaction, a solid red disc with knocked-out rings, a multiply-blended black overprint for the second impression.

**Selected: A.** It is the more physical reading of the brief (paper, ink, bristle, seal) and its reveal reads at a glance — registered rings and a registration cross when both refused the same cost, a second ring knocked off-register with a tension line when they did not. B is bolder and graphic but reads as a poster, less as paper; its multiply overprint idea is kept as the `blendModeValue` option on the second impression. Switching is a one-argument change: `node rive/le-recu-paper/tools/gen-scene.mjs press rive/le-recu-paper` then `npm run rive:build`.

## The contract (Rive is a projection, never a source of truth)

`src/lib/rive-paper-contract.ts` is the single adapter. The scene exposes four numbers and nothing else.

| property | meaning |
| --- | --- |
| `phase` 0..7 | idle, ink, pending, sealed, waiting, reveal, failed, unavailable |
| `outcome` 0..2 | none / same / different — only non-zero in `reveal`, derived from a verified duel |
| `markKept` 0/1 | in `failed`: keep the local ink mark (creator) or let it fade (guest) |
| `proximity` 0..1 | cosmetic nearness of the pointer to a cost line; never persisted |

Derivation: `experiencePhase()` (existing, unchanged) + the in-flight action + the visible error. `waiting` requires a server-issued id, owner role, pending status **and** the creator's mark; `reveal` requires status `complete`, a participant role and two indices. `experience-state`'s `seal` means "a choice exists locally", so it maps to `ink`, never to a seal. The one-shot `sealed` impact is added by React only on a `pending → waiting` transition, so a page reload into a pending duel does not replay the stamp.

The `.riv` contains: no scripts, no listeners that write state, no text, no cost labels, no identity, no counters. Cost text, the person's own refused label and all decisions stay in React/HTML. The canvas is `aria-hidden`, `tabindex=-1`, `pointer-events: none`, Rive's own pointer listeners are disabled.

Two product-truth fixes made along the way:
1. The HTML "DÛ" stamp used to render as soon as a choice existed locally, i.e. **before** `createDuel` returned. It is removed; the seal now exists only in the stage (Rive, or its SVG twin), only after confirmation.
2. `data-receipt` was keyed on `theirs`, which remounted the card — and would have remounted the Rive canvas — at reveal. It is now keyed on the receipt only, so the second impression prints onto the same canvas.

Fallback ladder (decisions keep working at every rung): Rive canvas → SVG/CSS twin with the same phases (before load, reduced motion, no WebGL2, load error, render crash via error boundary). A live region mirrors the phase in plain FR/EN (`ui.*.paper`).

## Known limits and honest caveats

- PGlite is not Neon. Latency, cold start and the real 72 h expiry were not exercised, so the `pending` texture was only seen briefly.
- Software GL (SwiftShader) was used; frame rate and thermal behaviour on a real low-power iPhone are unknown.
- Rive pauses off-screen canvases. The stage therefore scrolls itself into view for `sealed`, `failed` and `reveal` (smooth, instant under reduced motion); this was added after a captured stale frame showed the creator's reveal animating unseen.
- No automated accessibility audit (axe) and no real screen reader pass. Verified: semantic buttons untouched, canvas hidden from AT, a polite live region per phase, focus order unchanged, keyboard path, reduced motion.
- The stage adds 96 px (idle) / 176 px (active) above the cost list on mobile; the list still scrolls into reach but the first screen shows fewer rows than V1.3. Worth an owner decision.
- The Rive CLI is pinned at 1.5.1 (1.6.0 exists); not upgraded mid-task so provenance stays reproducible.
- Cadet account use: signed-in session confirmed, **no file pushed, nothing overwritten**. A Rive-editor copy can be created later with `rive push` on explicit approval.
